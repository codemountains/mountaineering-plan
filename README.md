# 登山計画

山岳気象・登山ルート・公共交通アクセス・現地コンディションを統合し、登山計画の意思決定を支援する AI 向けの指示と参照資料です。ChatGPT のプロジェクト機能、または ChatGPT / Codex 向けプラグインで利用できます。

「その日に、その山へ、その交通手段で行き、安全マージンを確保しながら登山し、その日のうちに帰宅できるか」を、登山口へのアクセスから帰宅まで一貫して評価します。

## 主な機能

- **山岳気象の分析**：高層天気図や数値予報モデルを比較し、標高・地形・行動時間帯に応じて風、降水、雷などを評価します。
- **公共交通の検証**：対象日の運行、乗換、予約、登山口までの移動、帰宅可能な最終接続を確認します。
- **登山ルートの評価**：通行規制、距離、累積標高、コースタイム、技術的難所、積雪・凍結などを確認します。
- **時間と余裕の管理**：休憩や疲労を含む行動時間、通過期限、撤退時刻、最終交通までの余裕を具体化します。
- **代替案の提示**：天候悪化や交通逸失に備え、短縮ルート、別登山口、代替交通、別山域などを検討します。

## 評価の考え方

計画を次の 5 条件で評価します。

| 条件 | 確認すること |
| --- | --- |
| ACCESS | 登山口まで現実的に到達できるか |
| TRAIL | ルート、登山道、体力、技術面で成立するか |
| WEATHER | 行動時間帯・標高帯の気象条件が許容範囲か |
| RETURN | 安全に下山し、帰宅交通へ接続できるか |
| MARGIN | 遅延、疲労、混雑、天候悪化などを吸収する余裕があるか |

登頂だけでなく、合理的な撤退、安全な下山、帰宅までを計画に含めます。最終交通、通行止め、雷などの変更必須条件を優先し、計画全体の最大の制約を特定します。

## 使い方

### プラグインで使う

プラグインの実装はすべて [plugin/](./plugin/README.md) にあります。ローカル marketplace への登録・インストール・更新方法は、[プラグインの利用手順](./plugin/README.md#ローカルで使う)を参照してください。

### ChatGPT のプロジェクトで使う

1. 登山計画用のプロジェクトを作成します。
2. [project-instructions.md](./project-instructions.md) の内容を「プロジェクトの指示」欄にコピーします。
3. [mountaineering-plan.md](./mountaineering-plan.md) をプロジェクトのソースに追加します。基本指示を設定する操作と、ソースを追加する操作の両方を行ってください。
4. プロジェクト内で山行ごとにチャットを作り、予定日、対象の山やルート、出発地などを添えて質問します。例：`2026-11-07 岩手山 日帰り計画`。
5. 気象・運行・通行規制などの最新確認が必要な質問では、Web 検索・資料閲覧を使える環境で実行します。

基本指示は全チャットで使うルール、詳細資料は質問に応じて参照する手順・判断基準です。README 自体をソースに登録する必要はありません。

### 更新するとき

ローカルの Markdown を編集しただけでは、アップロード済みのソースが更新されたとみなさないでください。詳細資料の版番号・更新日を更新し、プロジェクト側のソースも差し替えます。旧版を併存させず、利用する版を一つにそろえてください。基本指示を変更した場合は「プロジェクトの指示」欄も更新します。

### プロジェクト機能がない AI で使う

[project-instructions.md](./project-instructions.md) を指示欄または会話の冒頭に貼り付け、詳細資料を添付するか、利用可能なコンテキスト内で本文も提供してください。資料を参照できない場合は、参照できていない範囲を明示して利用します。

最新の気象・運行・通行規制を確認するため、Web 検索や公式資料の閲覧ができる AI 環境での利用を想定しています。プロンプト自体にデータ取得機能はありません。閲覧できない情報は、資料を提供するか、未確認として扱うよう指示してください。

### 登山経験・装備を繰り返し使う場合

必要なら以下を記入した `user-profile.md` を別のソースとして追加します。未記入の項目は未確認として扱います。山行日・希望ルート・同行者・当日の体調・帰宅期限は山行ごとのチャットに記載し、過去の山行条件と混同しないようにします。

```text
# 登山プロフィール
確認日：YYYY-MM-DD
通常の出発駅：
通常の交通手段：
経験のある地形・季節：
経験が少ない地形・季節：
所有・使用経験のある装備：
通常のペースの参考実績：
- 山行日・ルート：
- 距離・累積標高・路面・荷物：
- 歩行時間（休憩を除く）：
- 休憩時間：
```

今回の申告・訂正を優先します。所有装備は今回携行する装備と区別し、プロフィールを更新した場合はプロジェクトのソースも差し替えてください。

### 総合計画の質問例

以下の角括弧内を実際の条件に置き換えて入力します。

```text
[YYYY-MM-DD] に [山名] への日帰り登山を検討しています。

- 出発地：[最寄り駅など]
- 交通手段：公共交通
- 希望ルート：[登山口・経由地、または未定]
- 登山経験：[最近の山行、所要時間、累積標高など]
- 装備：[利用できる装備]
- 帰宅希望時刻：[時刻]

往復交通、登山道の状況、気象、行程、撤退時刻、
最終交通までの余裕、代替案を含めて計画してください。
確認状況と、予測・推定・仮定などの情報の種類を区別し、
重要な判断の出典・対象日時・更新日時・確認日時を示してください。
```

### 個別の質問例

- 気象：「[日付] の [山名] は、午前中の稜線風と午後の雷に注意が必要ですか？」
- 交通：「[日付] に [出発駅] から始発で向かう場合、[登山口] で何時に登山を開始できますか？」
- ルート：「[日付] の [ルート名] について、通行規制と積雪・凍結の状況を確認してください。」
- 比較：「[日付] に公共交通で日帰りするなら、[山 A] と [山 B] のどちらが時間に余裕を持てますか？」

質問の範囲に応じて、気象・交通・登山道・総合計画の各モードを使い分ける設計です。

## 回答で確認できること

総合計画では、成立性の結論、成立条件、往復交通、ルートと行程指標、推奨タイムライン、撤退時刻、気象・登山道状況、時間余裕、リスク、不確実性、装備・補給、代替案、使用データを整理します。通常は重要事項をまとめた標準回答とし、詳細が必要な場合は元の全出力項目から展開します。「詳細版で全項目を確認してください」と指定することもできます。

撤退時刻は、最終交通・気象悪化・日没などの制約ごとに到達先を定めて逆算します。登山口から乗り場までの徒歩を含め、休憩・乗車準備・安全余裕を重複して計上しません。

計画の判断は、次の区分で示します。

| 判定 | 意味 |
| --- | --- |
| PENDING（判定保留） | 成立性を左右する情報が未確認。確認事項と暫定案を提示 |
| GO | 余裕を持って成立 |
| CONDITIONAL GO | 特定条件下で成立 |
| MARGINAL | 成立するが余裕が小さい |
| PLAN CHANGE RECOMMENDED | ルート・時間・山域の変更を推奨 |
| NO-GO | 変更必須条件への違反、または重大な安全リスクあり |

情報は公式・公的情報を優先します。確認状況は CONFIRMED / UNVERIFIED、当日の状況まで確認できた場合は LIVE を併記します。情報の種類は OBSERVED / SCHEDULED / FORECAST / ESTIMATED / ASSUMPTION / HISTORICAL で区別します。例えば、確認済みの公式予報は CONFIRMED / FORECAST であり、予報の的中を保証する意味ではありません。判断の確信度も HIGH / MEDIUM / LOW で示します。

既に重大な危険や規制違反を確認した場合は NO-GO を優先します。重要情報が不足しているだけの場合とは区別します。

## 改訂後の確認

詳細資料の付録Aに、日付不足、資料の取得不可、予報期間外、公式閉鎖、交通逸失などの回答例があります。プロジェクトに設定した後は、実際のチャットでこれらの条件を試し、次を確認してください。

- 個別質問に不要なフルフォーマットや解析を追加していないこと。
- 取得できない時刻表・モデル・予報を確認済みとせず、必要なら判定保留にすること。
- 制約ごとの撤退時刻と到達先、乗り場までの移動、バッファの計算が整合すること。
- 今回のユーザー条件を優先し、別の山行の経験・装備・時刻を流用していないこと。

文書上の整合性確認と、実際の ChatGPT での回答確認は別です。モデルや利用可能な検索・閲覧機能によって結果が変わるため、設定後の回答も確認してください。

## 利用上の留意点

AI の回答は登山判断を支援するもので、安全や運行を保証するものではありません。出発前と当日に最新の公式情報を確認し、現地の状況や自身の体力・技術に応じて計画変更・撤退を判断してください。
