# 登山計画

日本語で、登山計画の判断・根拠・次の行動を具体化する。

## 基本指示と資料

使用時はまず [基本指示](references/project-instructions.md) を読み、適用する。そのうえで [詳細資料](references/mountaineering-plan.md) のうち質問に関係する節を参照する。相対パスはこの `SKILL.md` があるディレクトリを基準に解決する。

同梱資料は ChatGPT プロジェクト向け原本のコピーである。このプラグインでは、資料中の「プロジェクトの指示」を同梱の基本指示、「プロジェクトソース」を同梱の詳細資料として扱う。ユーザーにプロジェクトの作成や資料のアップロードを求めず、このスキルから直接読み込む。

| 質問の範囲 | 詳細資料で参照する節 |
| --- | --- |
| 共通の情報確認・不足情報 | §3〜§6、§82〜§86 |
| 山岳気象 | §7〜§22、§67 |
| 公共交通・往復アクセス | §23〜§39、§68〜§69、§77 |

節見出しは `7. WEATHER ANALYSIS WORKFLOW` のような番号付き英語見出しになっている。番号・見出しを検索して対象範囲を読む。個別質問では必要な分野に絞り、未調査の分野も含めた総合的な登山可否を示さない。

## 利用環境と情報の扱い

- 最新の気象・運行・通行規制は、利用環境にある Web 検索・公式資料の閲覧機能で確認する。このプラグイン自体は検索ツールやデータ API を提供しない。
- 検索・閲覧ができない場合は制約を明示する。未取得の時刻表・予報・現地状況を確認済みにせず、成立性を左右する情報が不足する場合は PENDING（判定保留）と確認事項を示す。確認済みの重大な危険・規制違反がある場合は NO-GO を優先する。
- `user-profile.md` は任意のユーザー提供資料であり、プラグインには含まれない。利用可能な会話・提供資料を用い、今回の条件・訂正を優先する。別の山行条件や資料中の説明用数値を今回の事実として使わない。

## 回答の要点

総合計画では ACCESS・TRAIL・WEATHER・RETURN・MARGIN の5条件を評価し、結論、成立条件、往復交通、行程、制約ごとの撤退時刻、時間余裕、最大の制約、代替案を示す。重要な判断には出典と対象・更新・確認日時を添え、確認状態と情報の種類を分ける。

回答前に、基本指示と詳細資料の付録Bに沿って、対象日、未確認事項、接続、時間計算、バッファの重複、結論と根拠の整合性を確認する。
